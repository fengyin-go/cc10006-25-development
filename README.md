# 数据湖仓一体管理平台

面向数据湖仓一体架构下的多源异构接入、原始文件编目、湖内分区治理、流批一体转换、版本回溯与数据编目检索的管理平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 批处理失败隔离与重放

批量转换模块支持按分区隔离失败并从失败点重放，内置示例任务 `batch_orders_07`
（共 16 个分区，前 12 个成功后卡在第 13 个分区，依赖上游 `clean_orders`）。

- **重放范围**：`GET /api/batch/{id}/replay-scope` 按输入路径、分区覆盖、依赖上游
  识别可重放范围；重放只从最早失败分区开始，已成功分区的输出路径永不变化。
- **失败隔离重放**：`POST /api/batch/{id}/replay` 只处理失败分区及后续未完成分区，
  成功才写输出，再次失败即停止；同一任务并发重放只创建一个执行实例，重复提交合并到
  运行中实例，不重复写输出；非法分区范围返回 400。
- **失败清单**：`GET /api/batch/{id}/failures` 保留每次失败的时间、分区、处理脚本与
  依赖上游，可按脚本/上游定位；同分区多次失败以最早失败记录为准，新记录标注冲突。
- **重放实例台账**：`GET /api/batch/{id}/replay-instances` 记录每一次重放的分区范围与结果。
- **跨模块台账**：失败清单驱动质量异常台账（`quality`）与清洗待处理队列（`silver`），
  重放成功后自动核销；`POST /api/batch/sync-ledgers` 可手动对齐。
- 核验脚本：`python -I scripts/verify_replay_http.py`（真实 HTTP 服务，67 项断言）。
